# 小猪修修 0.6.0 人像精修与一键出片设计

**状态：** 已确认范围，等待最终规格复核  
**日期：** 2026-10-22  
**目标版本：** 0.6.0  
**兼容基线：** 0.5.1

## 1. 摘要

0.6.0 将小猪修修从“专业图层工具”扩展为“普通人也能从导入走到出片”的人像修图软件。版本核心是本地离线的人脸分析、人像精修、手动液化、可复用预设和批量出片。

本版本不引入云端服务，不上传图片，不依赖 Python、TensorFlow、MediaPipe 运行时或系统级模型安装。模型与推理运行时随程序分发。

## 2. 产品目标

用户在导入照片后，应当能够：

1. 自动看到合照中的每一张脸。
2. 选择一张脸并进行独立的皮肤、眼睛、牙齿、嘴唇和脸型调整。
3. 使用液化画笔手动调整脸部或身体轮廓。
4. 使用内置或自定义预设快速完成调色与人像精修。
5. 将同一套预设批量应用到文件夹中的图片。
6. 在每一步看到预览，并使用单步撤销恢复。

0.6.0 的完成标准是：新用户不阅读专业修图教程，也能在一个人像工作区内完成“导入、自动识别人像、调整、应用预设、导出”的完整流程。

## 3. 非目标

以下内容不属于 0.6.0：

- 云端 AI、账号体系、订阅、广告、付费入口或水印。
- 生成式填充、云端换脸、云端超分辨率。
- 模板市场、在线预设商店或社交分享。
- 自动身体关键点、自动瘦腰或自动长腿。
- RAW 文件的批量精修。
- 视频编辑。

自动身体塑形和多人分别保存不同预设属于后续 0.6.x。0.6.0 的身材调整通过手动液化完成。

## 4. 用户工作流

### 4.1 单张人像

1. 用户导入图片并打开“人像精修”工作区。
2. 程序在后台分析人脸，不阻塞画布操作。
3. 左侧显示人脸列表，画布显示编号、人脸框和当前选中脸的关键点轮廓。
4. 用户选择一张脸。
5. 用户调整皮肤、眼睛、牙齿、嘴唇或脸型参数，画布实时显示降采样预览。
6. 用户可切换“原图/效果”对比。
7. 用户点击“应用”，程序在全分辨率上执行一次可撤销操作。
8. 用户选择或导入预设，完成调色并导出。

### 4.2 多人合照

- 自动检测最多 8 张脸。
- 人脸按人脸框中心 X 坐标升序编号；X 相同时按顶部 Y 坐标升序，再按面积降序。
- 当前只编辑一张脸，切换人脸时保留该脸的参数直到用户应用或取消。
- 批量处理时，同一套人像参数应用到所有检测到的人脸。
- 小于 64 像素的人脸不参与自动精修，但仍可由用户手动液化。

### 4.3 批量出片

1. 用户选择输入文件夹和输出文件夹。
2. 用户选择一个 `.xzp` 预设。
3. 用户设置格式、质量、最长边、递归扫描和文件名后缀。
4. 程序逐张分析、应用预设并写入输出目录。
5. 单张失败不会终止整个批次；完成后显示成功、跳过和失败数量及错误列表。

## 5. 功能需求

### 5.1 本地人脸分析

- 自动检测正面和轻度侧脸。
- 输出人脸框、双眼关键点、置信度和 478 个三维面部关键点。
- 关键点包含 468 点脸网格和 10 个虹膜点。
- 检测置信度阈值为 0.5，人脸存在置信度阈值为 0.5。
- 人脸检测使用 128x128 RGB 输入，值域为 [-1, 1]。
- 关键点模型使用 256x256 RGB 输入，值域为 [0, 1]。
- 第一次裁剪基于检测框和双眼角度；第二次裁剪基于第一次关键点的脸框和双眼角度。
- 分析结果缓存在当前会话内；图片变化、图层替换或画布几何变化后重新分析。

### 5.2 皮肤精修

提供以下参数，范围均为 0 到 100：

- 平滑：降低低频肤色不均，保留五官边缘。
- 纹理：恢复毛孔和高频细节。
- 匀肤：减少局部色差和红斑。
- 祛痘：自动抑制皮肤区域中的小型高频异常点。

皮肤蒙版由脸轮廓、五官排除区、颜色分类和羽化共同生成：

- 默认排除眼睛、眉毛、嘴唇和鼻孔。
- 羽化宽度为脸宽的 6%。
- 皮肤蒙版不得越过人脸轮廓超过脸宽的 2%。
- 单次应用后保留原始高频细节，禁止出现塑料感平涂。

### 5.3 眼睛、牙齿与嘴唇

提供以下参数：

- 眼睛亮度：0 到 100。
- 眼睛清晰度：0 到 100。
- 黑眼圈减弱：0 到 100。
- 牙齿美白：0 到 100。
- 唇色强度：0 到 100。
- 唇色：RGBA 颜色，默认不改变原色。

眼睛和嘴唇区域由 478 点关键点生成羽化蒙版。牙齿美白只作用于嘴唇内轮廓和低饱和度亮色像素，不得改变唇色。

### 5.4 脸型与五官

提供以下参数，范围均为 -100 到 100：

- 脸宽。
- 下颌。
- 下巴。
- 眼睛大小。
- 鼻翼宽度。
- 嘴唇形状。

变形使用人脸区域的局部网格映射：

- 变形中心由对应关键点确定。
- 影响半径以脸宽为基准。
- 边缘权重使用平滑衰减。
- 反向映射采样防止网格裂缝和空洞。
- 参数为 0 时不改变像素。

### 5.5 手动液化

提供三种画笔模式：

- 推移。
- 收缩。
- 膨胀。

画笔参数：

- 直径 8 到 800 像素。
- 强度 1 到 100。
- 硬度 0 到 100。

液化在一个可撤销的手动变形会话中完成。用户可恢复到会话开始状态。液化可用于脸部和身体，不要求自动身体识别。

### 5.6 预览与应用

- 分析完成后，参数调整以最长边不超过 1024 像素的预览图呈现。
- 预览更新目标为 100 毫秒内完成；耗时操作必须显示进度状态。
- 用户可按住按钮或快捷键查看原图。
- 点击“应用”后在全分辨率图像上执行一次操作。
- 应用、取消和失败都必须恢复到一致状态。
- 成功应用只产生一个历史步骤。
- 取消应用不得改变图层像素或历史记录。

### 5.7 预设

预设分为：

- 内置预设：至少 8 个，覆盖自然、通透人像、暖调、冷调、胶片和黑白。
- 用户预设：保存到用户配置目录，可导入和导出。
- 批量预设：用户预设和内置预设均可用于批处理。

预设包含调色、颗粒、暗角和人像参数，不包含输出格式、目录、文件名或机器相关路径。

预设应用规则：

- 调色通过一个 `ColorGrade` 调整层和可选的颗粒、暗角滤镜层完成，保持非破坏性。
- 人像参数通过一次可撤销的像素操作应用。
- 整个预设应用属于同一历史事务；一次撤销恢复应用前的状态。
- 预设取值范围在加载时严格校验，非法预设不得产生部分修改。

### 5.8 批量处理

支持输入格式：

- JPEG
- PNG
- TIFF
- WebP
- BMP
- GIF 首帧
- HEIC/HEIF

支持输出格式：

- JPEG
- PNG
- TIFF
- WebP

批量参数：

- 输入目录。
- 输出目录。
- 递归扫描开关。
- 预设。
- 输出格式。
- JPEG/WebP 质量 1 到 100。
- 最长边缩放，范围 64 到 30000 像素；0 表示保持原始尺寸。
- 文件名后缀，默认 `_xiaozhu`。
- 同名文件覆盖开关，默认关闭。
- 人脸参数应用于全部检测到的人脸。

CLI 接口：

```text
xiaozhu-xiuxiu --batch <输入目录> --out <输出目录> --preset <预设.xzp>
  [--recursive] [--format jpeg|png|tiff|webp] [--quality 1..100]
  [--max-edge 0|64..30000] [--suffix _xiaozhu] [--overwrite]
```

`--preset` 在 0.6.0 的批量命令中为必填；不带预设的现有批量导出语法继续可用。

用户预设目录为 `Config::path()` 的父目录下的 `presets/`。Windows 默认位置为 `%APPDATA%\xiaozhu-xiuxiu\presets\`，Linux 默认位置为 `$XDG_CONFIG_HOME/xiaozhu-xiuxiu/presets/` 或 `~/.config/xiaozhu-xiuxiu/presets/`。

写入规则：

- 输出先写入同目录临时文件，成功后再原子替换。
- 未开启覆盖时遇到同名文件记为跳过。
- 任何单张失败不得终止其他图片。

容器：UTF-8 JSON

    "vibrance": 12.0,

    "grain": 4.0,

  "portrait": {

## 7. 模型与许可

### 7.1 推理运行时

- 使用 `tract = 0.23.9`，关闭默认特性，只启用 `onnx`。
- 项目最低 Rust 版本从 1.88 提升到 1.91。
- 模型通过 `include_bytes!` 嵌入可执行文件，运行时不读取外部模型路径，不访问网络。
- 模型在第一次进入人像工作区时延迟加载，不影响普通启动路径。

### 7.2 模型资产

`assets/models/blazeface.onnx`

- 来源：Google MediaPipe BlazeFace short-range，ONNX 转换版。
- 许可：Apache-2.0。
- 大小：418,437 字节。
- SHA-256：`02a04d5d37c3558dc4d5274f7f8f0f0f01ac94e46c5ffb2cee82395d47e23181`
- 输入：`input`，`[1,128,128,3]`，float32。
- 输出：`regressors [1,896,16]`，`classificators [1,896,1]`。

`assets/models/face_landmarks.onnx`

- 来源：Google MediaPipe Face Mesh V2 与虹膜模型，ONNX 转换版。
- 许可：Apache-2.0。
- 大小：4,920,995 字节。
- SHA-256：`7d6e82dee82a1dca5fbddb282b3cc74571833a530de317fc22ae325c3358beeb`
- 输入：`input_12`，`[N,256,256,3]`，float32。
- 输出：`Identity [N,1,1,1434]`、`Identity_1 [N,1,1,1]`、`Identity_2 [N,1]`。

两个模型及转换说明必须登记到 `THIRD_PARTY.md`，并在 `licenses/` 中保存 Apache-2.0 文本和来源说明。

## 8. 组件与职责

### 8.1 核心库

- `src/portrait/mod.rs`：公开类型、错误类型和模块边界。
- `src/portrait/inference.rs`：模型加载、预处理、BlazeFace 解码、NMS、关键点推理。
- `src/portrait/geometry.rs`：人脸框、旋转裁剪、关键点坐标变换和稳定编号。
- `src/portrait/masks.rs`：脸轮廓、皮肤、眼睛、嘴唇和牙齿蒙版。
- `src/portrait/retouch.rs`：皮肤、瑕疵、眼睛、牙齿和唇色处理。
- `src/portrait/warp.rs`：脸型变形和液化网格。
- `src/portrait/preset.rs`：`.xzp` 序列化、验证、内置预设和用户预设目录。
- `src/batch.rs`：批量扫描、命名、处理、原子写入和报告。

### 8.2 桌面界面

- `src/app/portrait.rs`：人像工作区、人脸选择、参数状态、预览和应用事务。
- `src/app/portrait_controls.rs`：人像参数控件、前后对比和液化画笔控件。
- `src/app/batch_dialog.rs`：批量任务配置、进度、取消和错误报告。

### 8.3 现有模块扩展

- `src/document.rs`：增加 `ColorGrade` 调整变体。
- `src/effects.rs`：实现 `ColorGrade` 的 CPU 处理。
- `src/gpu.rs`：实现 `ColorGrade` 的 GPU 处理；不支持时回退 CPU。
- `src/app/jobs.rs`：增加可取消的人脸分析任务，不与文档修改任务共用错误语义。
- `src/app/menus.rs`、`src/app/dialogs.rs`：增加人像和批量入口。
- `src/main.rs`：增加批量 CLI 参数。

## 9. 数据模型

### 9.1 分析结果

```rust
pub struct FaceAnalysis {
    pub id: u32,
    pub bounds: [f32; 4],
    pub landmarks: Vec<[f32; 3]>,
    pub detection_confidence: f32,
    pub presence_confidence: f32,
}
```

坐标以当前文档像素为单位。ID 在当前分析结果内稳定；切换人脸或重绘不会改变 ID。

### 9.2 人像参数

人像参数使用明确的 `f32` 字段，不使用任意键值表。所有字段在应用和前均经过范围验证。

### 9.3 液化会话

液化保存：

- 原始图层像素。
- 网格尺寸。
- 控制点及其位移。
- 画笔操作序列，用于会话内撤销。

应用到文档前生成新像素；生成失败时保留原始像素。

## 10. 数据流

### 10.1 单人像分析与预览

```text
图层像素
  -> RGB 缩略图
  -> BlazeFace
  -> 人脸框与眼部关键点
  -> 旋转方形裁剪
  -> Face Mesh
  -> 478 点坐标映射回文档
  -> 蒙版与预览参数
  -> 降采样预览
```

### 10.2 应用

```text
分析结果 + 人像参数 + 原始图层
  -> 全分辨率蒙版
  -> 点处理与局部滤镜
  -> 网格变形
  -> 新图层像素
  -> 单一历史事务
```

### 10.3 批量

```text
文件扫描
  -> 解码
  -> 人脸分析
  -> 全部人脸应用预设
  -> 输出尺寸与格式
  -> 临时文件
  -> 原子替换
  -> 汇总报告
```

## 11. 错误处理

- 模型加载失败：人像工作区显示明确错误；普通编辑、调色和不需要人脸关键点的手动液化继续可用。
- 没有检测到人脸：显示“未检测到人脸”，允许手动液化，不自动应用人像参数。
- 关键点置信度过低：该脸标记为低置信度，不参与批量自动精修。
- 预览失败：回退到更低分辨率重试一次；再次失败则显示错误且不修改文档。
- 全分辨率应用失败：恢复原图层和历史记录。
- 预设加载失败：显示文件路径和具体字段错误，不应用任何部分。
- 批量单张失败：记录错误并继续，最终报告包含文件名和原因。
- 磁盘写入失败：删除临时文件，保留原文件并记录失败。
- 用户取消：停止后续处理；已完成文件保留，未完成文件不产生半成品。

## 12. 性能与资源约束

- 普通启动不加载模型。
- 首次进入人像工作区允许最多 2 秒模型初始化；期间界面保持响应并显示进度。
- 在一张 24MP、最多 8 张脸的图片上，分析目标为 3 秒内完成，使用四核桌面 CPU。
- 参数预览在分析完成后目标为 100 毫秒内更新。
- 批量处理逐张执行，避免同时持有多张大图。
- 内存峰值不得超过原图、预览图和一张分析图的组合所需范围的 2 倍。
- 模型嵌入后，Windows 与 Linux 发行包允许增加约 8 到 12 MB 压缩体积。

## 13. 隐私与兼容性

- 所有推理在本地完成。
- 程序不记录、不上传、不缓存可识别个人身份的生物特征数据。
- 分析结果只存在于当前进程内存，不写入 `.xuan`、日志或恢复快照。
- 0.6.0 能打开全部 0.5.1 `.xuan` 工程。
- 0.6.0 不改变 `.xuan` 扩展名。
- 新保存的包含 `ColorGrade` 的工程不承诺能被 0.5.1 打开；0.6.0 必须向后兼容旧工程。
- `.xzp` 是独立格式，不嵌入工程文件。

## 14. 测试与验收

### 14.1 自动化测试

- BlazeFace 输出形状、anchor 解码、阈值和 NMS。
- 双眼旋转裁剪与坐标往返误差小于 0.5 像素。
- 478 点输出解析和虹膜索引映射。
- 皮肤蒙版包含脸颊并排除眼睛与嘴唇。
- 参数为 0 时像素逐字节不变。
- 肤色处理保持 alpha 和 16-bit 数据路径。
- 液化反向映射无空洞、边界无裂缝。
- 预设序列化往返、范围校验和未知版本拒绝。
- 批量命名、同名跳过、原子写入和单张失败继续。
- 应用成功只产生一个历史步骤；取消不改变文档。
- GPU 与 CPU 的 `ColorGrade` 结果误差不超过 1 个 8-bit 级。
- 模型零输入推理只验证形状和有限数值，不要求检测到人脸。

### 14.2 集成测试

- 单脸图片进入工作区后显示一张脸并完成一次应用。
- 多脸图片按从左到右编号并可独立切换。
- 预设应用后一次撤销恢复调色与人像变化。
- 批量处理成功、跳过、失败三种结果同时出现在报告中。
- 取消长时间批量任务后无残留临时文件。

### 14.3 人工验收

使用本地提供的真实人像和合照检查：

- 皮肤没有明显塑料感。
- 眼睛、牙齿和嘴唇没有越界。
- 脸型变形没有背景拖拽和网格裂缝。
- 多人脸编号与选择稳定。
- 批量输出与非批量单张应用结果一致。

真实测试照片不提交到仓库，避免第三方肖像和数据许可问题。

## 15. 关键设计决策

1. 采用 ONNX + `tract`，不使用 MediaPipe/TensorFlow 运行时。
2. 采用两个 Apache-2.0 模型：BlazeFace 和 Face Mesh。
3. 模型嵌入程序，首次使用时延迟加载。
4. 人像精修以可撤销的像素操作应用，不在 0.6.0 引入新的可编辑人像图层类型。
5. 调色预设使用 `ColorGrade` 调整层，保持非破坏性。
6. 多人合照只编辑当前选中脸；批量时应用到全部脸。
7. 身材调整采用手动液化；自动身体关键点延后到 0.6.x。
8. 批量逐张处理，优先稳定性和内存上限，不追求并发吞吐。
